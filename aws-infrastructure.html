AWS Cloud Infrastructure

Outcome: a segmented AWS network where each server accepts only the traffic and identities it needs. Two public subnets in separate Availability Zones, each with its own route table and a web server, plus a static website on S3.

Overview Decisions Architecture Checks Issues What's next

What I built

A segmented AWS network in one VPC. Two public subnets sit in separate Availability Zones, each with its own route table and a web server. A static website is served from S3, separate from the servers.

Back to top ↑

Decisions

  • Two Availability Zones. If one zone has an outage, the other subnet and its server keep running.
  • A route table per subnet. A subnet is public only when its route table sends 0.0.0.0/0 to the internet gateway.
  • One security group per job. Admin SSH is open only from my IP address. Web traffic is HTTP on port 80. The internal group allows all TCP traffic between the two servers.
  • Access by role. The developer policy allows EC2 actions only on instances tagged Env=development, and an explicit deny blocks tag changes.
  • Systems Manager for administration. The servers' role lets Systems Manager manage them without an open SSH port.
  • Website in S3. The bucket allows public reads of the site files only, through s3:GetObject.

Checks

  • SSH works from my IP address and is refused from elsewhere.
  • The website loads from the bucket's website endpoint, and anonymous uploads are refused.
  • The two servers can reach each other through the internal security group.
  • dev-engineer can see and stop instances tagged Env=development, and can't change tags.

What broke and how I fixed it

  • SSH refused the key with UNPROTECTED PRIVATE KEY FILE. Other users on the computer could read the key file. Fix: chmod 400 on the key.
  • SSH stopped working. My home IP address had changed, so the admin rule no longer matched. Fix: I updated the rule to my current address, and I use Systems Manager when I can.
  • A server couldn't install updates. Its subnet's route table had no 0.0.0.0/0 route to the internet gateway. Fix: I added the route and checked the subnet association.
  • The website returned 403 Forbidden. The bucket policy was missing, or a Block Public Access setting still blocked it. Fix: I reviewed the policy and the four settings.
  • A developer got "not authorized" errors. The instance was missing the Env=development tag, so the developer policy didn't apply. Fix: I added the tag.
