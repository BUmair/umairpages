Serverless REST API

A REST API for a simple items list. API Gateway receives requests, a Lambda function runs the logic, and DynamoDB stores the data. Cognito protects the write routes with JWT tokens.

Overview Architecture Routes Build steps Verification Issues I hit What's next Cleanup

Overview

Reads are public, and writes need a signed-in user:

  • Public reads. Anyone can list items or get one by ID.
  • Protected writes. Creating and deleting items require a Cognito ID token. Without one, the API returns 401.
  • Least privilege. The Lambda's role can use only the four DynamoDB actions it needs, on the one table.
  • Logging. Each request writes a line to CloudWatch Logs.

Architecture

The client signs in with Cognito to get a token. API Gateway checks the token on the write routes, then invokes the Lambda function.

Build steps

  1. DynamoDB: create table items with partition key id (String), on-demand capacity.
  2. Cognito: create a user pool with email sign-in and a single-page app client with no secret. Enable the username-and-password flow.
  3. Lambda: create items-api on Python 3.12. Set the handler to lambda_function.handler and add the environment variable TABLE_NAME=items.
  4. Permissions: add an inline policy that allows Scan, GetItem, PutItem, and DeleteItem on the table's ARN only.
  5. API Gateway: create an HTTP API, add the four routes, and attach one shared Lambda integration to all of them.
  6. Authorizer: create a JWT authorizer with the user pool's issuer URL and the app client ID as the audience. Attach it to POST and DELETE only.
  7. Deploy: create the $default stage with auto-deploy on.
