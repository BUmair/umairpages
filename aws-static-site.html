Static Site on S3 + CloudFront

Outcome: a website that serves over HTTPS from a private S3 bucket. Direct S3 access is denied, and only the CloudFront distribution can read the bucket.

Overview Decisions Architecture Verification Issues Reproduce it What's next

What I built

A static website served from a private S3 bucket through CloudFront. The bucket stays closed to the public. Only this one CloudFront distribution can read it, so visitors get the site over HTTPS and nobody can reach the bucket directly.

Back to top ↑

Decisions

  • Private bucket. All four Block Public Access settings are on, and versioning is enabled.
  • Origin Access Control. CloudFront signs each request to S3. OAC works with the S3 REST endpoint, not the website endpoint, so the origin is the REST endpoint.
  • Scoped bucket policy. It allows only s3:GetObject, only for the CloudFront service, and only for this distribution.
  • HTTPS only. CloudFront redirects HTTP requests to HTTPS.

Back to top ↑

Architecture

A visitor's request goes to CloudFront, which fetches the file from S3 with a signed request. A direct request to the S3 URL is denied.

Back to top ↑

How I verified it

  • The CloudFront URL for / returned 200 and the page rendered.
  • The direct S3 object URL returned AccessDenied, so the bucket is not reachable without CloudFront.

Back to top ↑

What broke and how I fixed it

Symptom: CloudFront returned AccessDenied for /, even though the bucket policy and OAC were set up correctly.

Cause: The distribution's default root object was blank. A request for / asked S3 for an empty key, and the policy grants only s3:GetObject, so S3 denied it.

Fix: I set the default root object to index.html.
